# VULN-003 비밀 문의(Q&A) 접근제어 미흡 (본문이 상세 API에 그대로 노출)

- 대상 스택: node-express, java-spring (client 공통)
- 심각도: Medium
- 분류: A01:2021 Broken Access Control (CWE-639 / CWE-200)

## 위치

Q&A 문의글의 "비밀글(`secret`)" 여부와 무관하게, 문의 상세 API가 `body`(및 관리자 `answer`)를
모든 요청자에게 그대로 반환한다. 비밀글 마스킹이 **클라이언트에서만** 이루어져, API를 직접 호출하면
누구나(비회원 포함) 타인의 비밀 문의 내용을 열람할 수 있다. 목록 API는 제목만 내려주지만, 상세
API가 본문을 제한 없이 반환하는 것이 결함이다.

- node: `apps/node-express/src/routes/qna.js`, `GET /api/qna/:id` — `secret` 플래그를 응답에 포함하지만
  `body`를 세션/소유권 확인 없이 그대로 반환.
- java: `apps/java-spring/.../controller/QnaController.java`, `detail` — 동일(`toDetail`이 `body`를 무조건 포함).
- client: `apps/client/src/pages/QnaDetail.jsx` — 작성자/관리자가 아니면 본문을 "🔒 비밀글입니다"로
  가리지만, 원본은 이미 네트워크 응답에 실려 있다.

## 트리거 방법

```
GET /api/qna/3        (비인증 요청도 무방; 3 = 시드된 비밀 문의)
→ secret=true 인 문의의 body 가 응답 JSON에 그대로 포함됨
```

브라우저 DevTools의 Network 탭이나 curl로 상세 엔드포인트를 직접 호출하면, 화면에서 가려진 비밀
문의 내용을 그대로 열람 가능하다.

## 영향

- 다른 사용자가 비공개로 남긴 문의(주문/결제/개인정보 확인 요청 등 민감 내용) 노출 — 정보 유출.
  Q&A 특성상 결제·세금계산서·계정 확인 등 민감한 요청이 비밀글로 올라오므로 실질 피해가 크다.

## 증거 (재현 확인)

2026-08-28, 클린 재시드 후 로컬 재현(양 스택 동일): 시드된 비밀 문의(id=3, "(비밀글) 결제 영수증
재발급 문의")를 인증 없이 `GET /api/{node,java}/qna/3` 호출 → 응답에 `secret:true`와 함께
`body`("세금계산서 처리 때문에 영수증 재발급이 필요합니다...") 원문이 포함되어 반환됨을 확인.

## 조치 상태: 미조치 (의도된 취약점)

정상 구현: 서버에서 세션 사용자를 확인해 비밀 문의는 작성자(`user_id` 일치)와 관리자에게만 `body`를
내려주고, 그 외에는 필드를 제거하거나 마스킹 값으로 대체한다. 목록에서 이미 제목만 노출하듯,
상세도 접근 주체에 따라 본문 노출을 서버에서 통제해야 한다. 비밀 후기 노출(VULN-026)과 동일한
계열의 결함으로, 새 Q&A 게시판 표면에서 재발한 형태.
