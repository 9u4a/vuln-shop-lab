# 51. 로그인 후 원위치 복귀

브랜치: `feature/auth-token-batch` · 관련 취약점: [VULN-041](../vulnerabilities/VULN-041-open-redirect-login.md)

## 무엇을 만들었나

- 로그인 성공 후 원래 가려던 경로로 돌아간다. 이전에는 로그인하면 **무조건 홈(`/`)**으로 이동
  (`Login.jsx`가 `navigate('/')` 고정)했다.
- 복귀 대상은 `?next=` 쿼리 또는 `RequireAuth`가 넘겨주는 `location.state.from`에서 읽는다
  (`RequireAuth`는 이미 `state={{ from: location }}`를 넘기고 있었으나 로그인 화면이 무시하던 상태였다).

## 설계 판단

- 보호 페이지(마이페이지·주문 등)에서 로그인으로 튕겼다가 다시 그 페이지로 돌아오는 흐름은 커머스에서
  기본적인 UX라 추가했다. 삽입 지점이 이미 반쯤 배선돼 있어 자연스러웠다.
- 복귀 대상 검증을 의도적으로 넣지 않아 오픈 리다이렉트가 성립한다(VULN-041).

## 이후 변경

- 정상화 시: `next`를 동일 오리진 상대 경로로만 허용(예: `/`로 시작 + `//` 차단), 절대 URL·외부 스킴은 거부.
