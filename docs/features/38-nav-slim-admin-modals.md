# 38. 상단 메뉴 정리 · 관리자 등록 모달화 · 상품 상세/수정

브랜치: `feature/nav-slim-admin-modals`

## 무엇을 만들었나

**A. 상단 메뉴 정리**
- `SiteHeader.jsx` 내비게이션에서 카테고리 링크(상의/바지/가방 등)를 제거하고 `전체` → `상품`
  단일 링크로 축약. `CATEGORIES` 매핑·미사용 import 제거.
- `SiteDrawer.jsx`(모바일 메뉴)도 동일하게 `카테고리` 섹션을 `쇼핑 > 상품` 단일 링크로 축약.
- 카테고리 필터 자체는 상품 목록 페이지의 필터에 그대로 남아 있어 탐색 기능은 유지.

**B. 관리자 등록·수정 폼 모달화**
- 상품·FAQ·공지사항·이벤트·쿠폰의 `추가`를 인라인 토글 대신 공용 `Modal.jsx` 팝업으로 전환.
- FAQ·공지사항·이벤트·쿠폰의 `수정`도 인라인 행 편집 대신 모달 팝업으로 전환(목록 행은 항상
  요약 표시만). 이벤트/쿠폰은 기존 `EventForm`/`CouponForm`을 추가·수정 모달에서 공용 재사용.
- `+ 추가`/`수정` 버튼 → 모달 오픈, 저장/닫기 시 닫힘(기존 페이징·목록은 그대로).

**C. 상품 상세보기 · 수정**
- 상품 목록 행의 `상세/수정` 버튼 → 모달에 상품 전체 필드 편집 폼 + 이미지 미리보기/업로드.
- 저장 시 `PUT /api/admin/products/:id` 호출(양 스택 기존 엔드포인트). `api.js`에 `updateProductAdmin` 추가.
- 생성/수정이 공용 `ProductFields` 컴포넌트를 재사용, `toForm`/`toPayload`로 응답↔폼↔페이로드 변환.

## 취약점 보존
- 신규 클라이언트 로직뿐이며 백엔드 엔드포인트/검증은 미변경. 상품 목록 검색 SQLi(VULN-001 등),
  기타 의도된 취약점 표면 불변.

## 검증
- client `npm run build` 무오류. 상품 상세/수정은 node `PUT /admin/products/:id`,
  java `@PutMapping("/products/{id}")` 양쪽 존재 확인.
